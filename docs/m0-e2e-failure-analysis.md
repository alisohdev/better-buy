### Recommended first repair

Start with **the saved-run fixture context in the dashboard**. It prevents 32 cases from exercising the Offers view, and the product entry rule and all 32 captures agree. A scoped fixture change has less risk than changing production routing. The likely edit is `apps/web/tests/dashboard.spec.ts` (the saved-run setup and its consumers). Read-only references are `apps/web/src/features/dashboard/initialWorkspace.ts`, `apps/web/src/features/dashboard/initialWorkspace.test.ts`, `apps/web/src/features/dashboard/Dashboard.tsx`, and `packages/shared/src/readModels.ts`.

After approval, run the following production-config check in PowerShell. It covers the 16 scenario titles across both projects, builds before serving, and saves separate failure traces.

```powershell
$env:CI = '1'
$env:PLAYWRIGHT_PORT = '3149'
pnpm --filter @better-buy/web exec playwright test dashboard.spec.ts --grep 'transient result GET|persistent result failures|the feed reads one product projection|background result failures|permanent or invalid result HTTP|long Retry-After|reconnect refreshes stale failed reads|a failed scan retains|saved feed supports|appearance menu changes|layouts, theme preference|small mobile keyboard viewport' --trace=retain-on-failure --output=test-results/m0-saved-entry-recovery
```
